# CI/CD Pipeline Patterns (Flutter Mobile)

## Standard pipeline stages

1. **Lint** — `flutter analyze`
2. **Test** — `flutter test --coverage`
3. **Build** — `flutter build apk` / `flutter build ios` / `flutter build appbundle`
4. **Security scan** — dependency audit, SAST on Dart code
5. **Deploy staging** — internal TestFlight / Firebase App Distribution
6. **Smoke test** — automated happy-path on staging
7. **Deploy production** — store submission or enterprise MDM (gated)

## Worker-agent style steps

Each step can be a reasoning agent (not just a script):

- **Code Review Agent** — PR diff, standards, test coverage gaps
- **Security Agent** — SCA (pub outdated, known CVEs), secrets scan, OWASP mobile checks
- **Deploy Agent** — generate pipeline YAML, version tags, rollback plan
- **SRE Agent** — post-deploy health checks, error budget, rollback trigger

## Flutter-specific CI

```yaml
# Example GitHub Actions shape (generated by Deploy Agent)
jobs:
  analyze: flutter analyze
  test: flutter test
  build-android: flutter build appbundle --release
  distribute: firebase app distribution / play internal track
```

## Rollback criteria

- Crash rate spike vs baseline
- Failed smoke tests on staging
- Critical security finding in release artifact
- Client/stakeholder rejection at release gate
